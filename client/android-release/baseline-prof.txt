# Baseline Profile for {{name}} ({{androidPackage}}), written by hand: the classes and methods on the cold-start path
# from Application.onCreate to the first Fabric frame, so ART compiles them ahead of time at install instead of
# interpreting them on the first launches. scripts/android-signing.mjs copies this file to
# android/app/src/main/baseline-prof.txt, which AGP reads for the app module (next to AndroidManifest.xml), merges with
# the profiles the androidx and kotlinx libraries ship, expands the wildcards against the program classes, lets R8
# rewrite it to the obfuscated names, and compiles it to assets/dexopt/baseline.prof(m) (in an AAB:
# BUNDLE-METADATA/com.android.tools.build.profiles/). androidx.profileinstaller installs it on devices whose store
# does not (sideloads, Android 7-8); Play installs it from the bundle. See docs/ANDROID_RELEASE.md.
#
# Rule syntax: [FLAGS]Lpackage/Class;->method(args)return for methods, Lpackage/Class; for classes.
# Flags: H hot, S startup, P post-startup. Wildcards: * any characters but '/', ** any characters, ? one character.
# Checked 2026-09-27 with AGP 8.12's own profile compiler (profgen) against the program of versionCode 28 (RN 0.86.3,
# expo 57, reanimated 4.5.1, worklets 0.10.1, screens 4.26.2, safe-area-context 5.7.0, svg 15.15.4, gesture-handler
# 2.32.0, async-storage 2.2.0, android-widget 0.22.1): every line parses and every rule matches classes, before R8
# and after it (about 2,650 classes and 25,000 methods once minified, on top of the libraries' own profiles).
#
# Not measured: a profile generated on a device with Macrobenchmark and the androidx.baselineprofile Gradle plugin
# would be exact (and could add a startup profile for DEX layout); this one is the startup path as read from the
# sources, and the JavaScript itself runs as Hermes bytecode, which the profile does not touch.
